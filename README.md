# Murdoku

Murdoku 邏輯謎題的出題器與遊玩介面。每一題都是程式即時產生的，而且保證不用猜、不用假設就能解開。

**線上遊玩：<https://tomatoguy0502.github.io/murdoku/>**

這是非官方的愛好者實作，與 Murdoku 的原作者及出版品無關。

## 規則

盤面是一張 N×N 的房屋平面圖，上面有 N 個人：N−1 名嫌疑人與 1 名死者。

- 每一列、每一行恰好站一個人。
- 盤面分成數個房間。格子上可能有物件：椅子、床、地毯可以站上去；桌子、植物、書櫃不能站。
- 每位嫌疑人有一條以上的線索，描述案發當時自己在哪裡。
- **兇手是唯一與死者同房間的人。**

把所有人放回正確的位置，再指認兇手，就破案了。

## 怎麼玩

先在右側選一個人（或上方的「無人」「橡皮擦」），再到盤面上操作：

| 選了什麼 | 單擊格子                     | 拖曳       | 長按 0.3 秒                            |
| -------- | ---------------------------- | ---------- | -------------------------------------- |
| 某個人   | 標記或取消「這個人可能在這」 | 一次標多格 | 把這個人放上去；對他站的格子長按則收回 |
| 無人     | 標記或取消「這格沒有人」     | 一次標多格 |                                        |
| 橡皮擦   | 清掉這格的標記與人           | 一次清多格 |                                        |

其他功能：

- **線索對照**：選中一個人時，他的線索提到的物件與房間會在盤面上標成黃色。
- **衝突提示**：兩個人同列或同行，或死者的房間超過兩人時，相關的人會被紅圈標出。
- **提示**：分三段，每按一次多透露一點——接下來能確定誰、為什麼、在哪一格。如果已經有人放錯，會先指出來。
- **復原與重來**：復原也可以按 `Ctrl/Cmd+Z`；一次拖曳算一步。
- **自動保存**：進度存在瀏覽器裡，每一題各自保存，重新整理後還在。
- **分享題目**：大小、難度與題號都在網址裡，同一個網址永遠是同一題。
- **亮色與暗色主題**：預設跟隨系統，按過之後記住你的選擇。

盤面大小從 4×4 到 10×10，難度分簡單、普通、困難三種。

## 出題的原理

題目不是從題庫挑的，而是照下面的流程現場產生：

1. **畫地圖**：隨機長出房間（數量是盤面大小的三分之二，大小刻意不平均），再撒上物件。
2. **決定答案**：隨機排一組每列每行一人的站位，並確保死者的房間剛好兩個人。
3. **列出線索**：把這組答案裡每個人身上所有為真的線索列出來。
4. **加線索直到解得開**：一條一條加，每加一條就讓求解器試一次。
5. **刪掉多餘的**：逐條拿掉試試看，求解器還解得開就真的刪掉。

唯一解不是搜尋出來的，而是線索逼出來的：求解器只做推理、從不假設，所以它解得完，就代表答案唯一，而且人也一定能不靠試誤解出來。

### 推理的級別

求解器的規則依人覺得的難度分成五級，並且永遠先用簡單的，卡住了才動用下一級。所以一題解到底用過的最高級別，就是它真正需要的難度。

| 級別 | 規則                                                                 |
| ---- | -------------------------------------------------------------------- |
| 1    | 單人線索（在某房間、在某物上、緊鄰某物）；某人位置確定後排除同列同行 |
| 2    | 某列或某行只剩一個人能站；兩人線索（同房、相對方位）                 |
| 3    | 某人只可能在某列或某行；獨處、性別、死者房間的人數推論               |
| 4    | 兩個人的組合推理；房間容量上限                                       |
| 5    | 三個人的組合推理；被整列或整行逼進房間的人數推論                     |

三種難度對應的是題目必須用到的級別：簡單是 1 到 2 級，普通剛好 3 級，困難是 4 到 5 級。

這張級別表是依推理的複雜度排的，還沒有經過大量實際遊玩的校準。

### 線索的種類

在某房間、站在某物件上、緊鄰某物件、與某人同房間、在某人的某個方位、獨自一人、與某性別的人同房間、是房間裡唯一的某性別。

## 開發

專案使用 [Vite+](https://viteplus.dev/)，指令都透過 `vp` 執行。

```bash
vp install      # 安裝相依套件
vp dev          # 啟動開發伺服器
vp check        # 格式、lint 與型別檢查
vp test         # 跑測試
vp run build    # 正式建置，輸出到 dist/
```

推送到 `main` 分支後，GitHub Actions 會依序跑檢查、測試與建置，然後發佈到 GitHub Pages。

### 目錄結構

依「這個檔案依賴什麼」分層，依賴只能由下往上：

```
src/
  core/          遊戲規則與演算法。純 TypeScript，不依賴 Vue，也不含任何顯示文字
    types.ts       型別與常數
    board.ts       產生地圖
    clues.ts       判斷線索是否成立
    solver.ts      推理求解器
    generator.ts   出題器
    hint.ts        提示
    bruteForce.ts  回溯搜尋，只在測試裡當對照組
  workers/       在背景執行緒出題，避免卡住頁面
  composables/   有狀態的互動邏輯：遊玩進度、出題、主題
  utils/         顯示用的文字與圖示
  components/    畫面
```

`core/` 可以單獨拿去別的地方用：

```ts
import { generatePuzzle, solve } from "./src/core";

const puzzle = generatePuzzle({ size: 6, seed: 42, minLevel: 3, maxLevel: 3 });
console.log(puzzle.clues, puzzle.solution, puzzle.murderer);

// 求解器會回傳每一步推理，以及用到的最高級別
const { solved, steps, level } = solve(puzzle);
```

### 測試怎麼確保正確

求解器的規則一旦寫錯，就可能排除掉正確答案，或把有多個解的題目當成唯一解。測試用一個完全獨立、只會暴力搜尋的求解器當對照組，檢查兩件事：

- 推理規則在任何情況下都不會排除真正的解，包括線索不足、解不完的題目。
- 出題器產生的題目確實只有一個解。
